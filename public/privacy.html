Privacy

Last updated 31 August 2026

Handback is a free tool with no accounts. This page is short because there is genuinely very little to describe. Questions, or a request to delete something, go to the project's issue tracker.

What the server stores

Your browser encrypts a handoff's contents with AES-256-GCM before anything leaves your machine. The server receives and stores only:

  • an opaque random id
  • a version number
  • the ciphertext and its initialisation vector
  • ISO timestamps and the expiry window you chose

There are no other columns in the database. No titles, no summaries, no search index, no account, no email address.

What the operator can and cannot read

The decryption key is generated in your browser and lives only in the URL fragment, the part after the #. Browsers do not send fragments to servers, so that key has never reached this server and the operator cannot decrypt anything stored here.

This is not zero-knowledge, and calling it that would be dishonest. The server ships the JavaScript that does the encrypting, so you are trusting that the code delivered to your browser is the code in the public repository. A Handback link is also a bearer capability: anyone holding the whole link, fragment included, can read the handoff. Treat the link the way you would treat the document itself, and remember that pasting it into a chat tool puts it wherever that tool keeps its history.

Deletion

Every handoff carries a retention window chosen at creation: 24 hours, 7 days (the default), 30 days, or never. The window runs from the last change rather than from creation, so a handoff someone is actively working on does not vanish underneath them.

When the window passes, the ciphertext is deleted: the moment anyone next requests it, and by a daily sweep at 03:17 UTC for the ones nobody comes back to. It is a real delete, and nothing recovers the content afterwards. A handoff created with "never" is kept until removed by hand, so open an issue with its id if you need one gone.

IP addresses

Creating a handoff sends your IP address to Cloudflare's rate limiter, which uses it as a counter key so that scripted spam costs something. It is not written to the database and the application does not log it. Reading or updating a handoff does not touch the rate limiter at all.

Storage in your browser

Handback keeps two settings in your browser's local storage: your colour theme, and whether writes require your approval. Both are preferences you set yourself, both stay on your device, and nothing but this site reads them. There are no cookies, no analytics, no tracking pixels and no third-party scripts, which is why you are not being asked to consent to any.

Third parties

Cloudflare hosts the site, serves it, runs the database and applies the rate limit, acting as a processor. Like any host it keeps its own request logs.

That is the entire list. Fonts are served from this origin rather than from Google, specifically so that visiting this site does not send your IP address to a third party.

Your rights

Under the GDPR you can ask what is held about you, ask for it to be deleted, and complain to a supervisory authority. In practice there is almost nothing to hand over: without your link, the operator cannot identify which rows relate to you, and cannot read them either.
